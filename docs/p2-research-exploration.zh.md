# P2：围绕研究问题发现和筛选论文

入口：[PAS → My research](https://d1ai8ldqsh81fz.cloudfront.net/research)，然后点 **My research & projects →**，创建或打开一个项目。原有 Papers 详情、Evidence、Wiki、Markdown、P1 的批注/比较/讨论，以及管理员分析页面均保留。

## 四项功能

| 功能 | 实际行为 | 证据与边界 |
| --- | --- | --- |
| Related work | 在 PAS 现有公开论文库中按标题、摘要搜索关键词或短语，显示匹配原因，可加入项目或进入筛选 | 字面匹配，不是全网文献搜索或语义相似度。最多从最新 500 篇匹配项中按命中短语数排序，显示 50 篇；超限提示缩小查询 |
| Method map | 展示项目论文与方法短语的连接；同时列出已记录的引用关系及研究者手工假设 | 方法必须在摘要/原文中逐字找到，并带版本及字符位置；“提到方法”不等于“使用了方法”。引用不等于支持结论；手工联系单独标为 Researcher hypothesis |
| Screening | 每位成员分别记录 Include / Exclude / Undecided 和理由；同一论文的不同判断并存，分歧明确显示 | 判断不会自动增删项目论文。纳入和排除要求理由；版本检查阻止覆盖自己的过期判断。未加入项目的候选只要已经保存判断，重新打开仍会出现在队列中 |
| Project updates | 项目创建人设定短语并启用后，服务器每 15 分钟检查新入库论文；提醒保存在项目内，可以逐人标记已读 | 按论文进入 PAS 的时间计，不承诺发表后 15 分钟内发现。每个项目/论文只生成一次；本人已读不影响其他成员。更改短语或重新启用从新基线开始，不补发历史库 |

方法地图最多检查 100 篇项目论文，每篇前 80 个原文章节和摘要。自动检测一组常见方法短语，并核对已有 `uses_method` 提取结果是否确实出现在原文。预览最多展示 8 篇论文和 8 个方法；下面的证据列表包含已找到的连接。没有连接不能解释为没有科学关系。

提醒搜索基于标题和摘要。尚未入库、仅在全文中提到关键词、尚无摘要或摘要后来才补全的论文，可能延后命中或不会命中；历史入库时间早于启用时间的论文不会补发。每次最多处理 1,000 篇匹配的新到论文，余项下次继续；页面显示最新 200 条提醒和最新 1,000 条筛选记录，并提示截断。创建人停用账号后项目自动扫描停止。

## 同事试用

1. 从 Slack 卡片进入 PAS，完成本人的 Slack 身份确认。打开 **My research → My research & projects →**。
2. 创建一个项目，写明研究问题。新项目默认只有本人能访问。
3. 在 **Related work** 输入例如 `Bayesian optimization, catalyst`，查看命中理由，选 **Add to project**。
4. 打开 **Method map**，点击方法高亮相关论文；展开连接，点 **Locate connection evidence** 查看原文。需要提出新联系时选择两篇项目论文，说明理由，可附最多两条已共享到项目的原文批注。
5. 在 **Screening** 逐篇保存纳入/排除理由。多人判断冲突时并列展示，不自动选赢家。
6. 在 **Project updates** 设置关键词和筛选标准，勾选 **Enable project updates** 并保存。筛选标准供人参考，不会被伪装成自动语义规则。`Check now` 可立即检查，日常由服务器定时运行。
7. 用 **Manage project members** 明确选择同事，再把项目链接发到自己的 Slack 小群。分享链接不会自动给群里所有人授权。

## 个人数据隔离

- 所有 P2 接口先检查当前项目成员资格；不同工作区、非成员、被撤销成员均不能访问。管理员身份不绕过项目权限。
- 私人笔记、收藏备注、私人聊天及机构分析数据不参与相关工作搜索或自动方法提取。
- 研究假设、筛选理由、关键词和提醒属于项目内容，对项目当前及未来成员可见。已读记录按本人保存。只有创建人能配置提醒；手工假设仅作者本人可移除。
- 撤销权限后接口立即拒绝访问；已打开页面在权限轮询、刷新或重新聚焦时清除项目内容。无法收回已经阅读、截图或自行保存的内容。
- 自动提醒目前显示在 PAS 项目页，不向 Slack 发送私人项目兴趣。既有作者监控 Slack 推送继续独立运行。

本轮不需要新的模型 API key，不调用 Jev 或生成模型，也不把项目问题或私人数据发送给外部模型。仍有现有 AWS 运行费用。Scholar/Outlook 邮箱接入是另一个数据入口，不属于本次 P2 变更。

## 运维与验收

新增五张表由 Alembic `0026` 管理。AWS 旧库采用限定五张表的增量创建，并验证列、主键和外键；遇到部分表结构会停止，不把其他历史迁移标记为完成。

`PAS_EXPLORATION_WORKER=1` 启用随后端生命周期运行的扫描器：启动时一次，然后每 900 秒运行。数据库项目行锁串行化扫描和规则修改，项目/论文联合主键保证去重；多副本运行仍共享这一约束。页面显示最后成功扫描时间，超过 45 分钟提示检查，包括启用后一次也没成功的情况。日志只记录异常类型，不记录私人关键词、论文题名或 SQL 参数。

发布流程：`deploy/exploration_aws.py --apply` 构建带 SHA-256 的不可变程序包并启动隔离 canary；成功后 `--promote` 切换后端。基于本次发布前保存的后端 15 程序包，仅叠加 P2 所需文件。前端由 `deploy/unified_frontend.py` 发布，受限旧报告和机构数据的访问规则保留。

正常回退只切回保存的后端任务版本及相应前端文件，不删除 P2 数据表。不要在已有用户数据时运行 destructive downgrade。部署脚本会拒绝在服务状态或候选文件已改变时盲目晋升；后续新版本需要重新确认基线。

这些测试核对来源定位、权限和功能流程；不等于自动证明方法可迁移、论文相关性或结论正确。
