## 权限边界

| 内容 | 普通成员 | 管理员 |
|---|---|---|
| 共享论文、摘要、已入库的全文和 Markdown | 可以 | 可以 |
| 自己的收藏、笔记与私聊 | 可以 | 可以 |
| 受邀小组讨论 | 可以 | 可以 |
| 他人的私聊、笔记和未受邀讨论 | 不可以 | 不可以 |
| 机构对比、归因分析、管理导出、旧分析静态报告 | 不可以 | 可以 |
| 分配 admin、停用账号、权限审计 | 不可以 | 可以 |

身份、权限及小组名单都在服务端检查。请求里伪造 user ID、API key 或绕过前端菜单不能取得管理权限。Jev 的固定服务端接口继续使用独立密钥，该密钥不能成为普通页面的登录凭据。

原分析界面的接口包含内部归因字段，因此共享论文使用明确限定字段的 catalog 接口，同时复用原页面组件；个人功能使用 reading / research 接口。管理员身份不改变个人数据的 owner/member 校验。

## 问答与分享

新阅读讨论只检索论文原文及公开书目信息；不调用机构排名、内部分类、人工审核、Wiki 管理内容或自然语言 SQL。论文、年份、标题、全文状态可以限定阅读范围；内部归因筛选不能用于阅读问答。空论文集合不会扩大成全库检索。生成回答前后、流式输出前会重新核对读者和讨论权限。

分享会创建一个新的小组讨论，只复制明确选中的消息。私人原讨论不被公开。移除成员后，该成员的后续访问立即被拒绝。

P0 之前的讨论没有可靠的内容权限标记，保留为受限历史：只有本来有权访问该讨论的管理员可以读取；不能追加 AI 回答或扩大分享。普通成员请创建新阅读讨论。没有删除旧历史，也没有给管理员查看其他人历史的后门。

## 网关、源站与文件

- 主 API 默认需要管理员权限；公开健康检查、Slack 登录及明确列出的阅读接口除外。公开 OpenAPI/Swagger 关闭。
- 独立机构服务每次向 PAS 检查同一个浏览器会话，权限服务不可用时拒绝返回数据。直接访问 ALB 也受同一检查。
- 旧前端、报告、CSV/JSON/JS 数据存于 S3 的 `protected-legacy/`，通过管理员 API 读取。
- CloudFront 将旧静态文件转到受保护的文件 API。S3 给 CloudFront 的读取权限只覆盖公开登录入口及 `reading/`，不能直读管理文件。
- 带身份的 API 使用 `no-store`，CloudFront 转发 cookie 且 API 缓存 TTL 为 0。已经下载到个人设备的资料无法追溯收回；撤权控制后续请求。
- 原有全量前端发布脚本和 CI 已改为发布到受保护前缀，避免以后部署重新公开静态数据。

## 数据库和发布

新增 `pas_admin_grants` 与 `pas_access_audit`，不增加管理员读取私有数据的权限。完整仓库迁移为 `0024`；当前旧生产镜像采用已校验的增量建表，不伪造完成其他尚未发布的迁移。初始化管理员只执行一次，之后撤销角色不会在重启时自动恢复。

本次沿用现有镜像，以校验 SHA256 的增量包发布。后续 CI 构建完整镜像时会移除旧增量启动命令及包定位环境变量，使用新镜像自带的入口，避免旧包覆盖新代码。云端临时验证账号在数据库事务回滚或 `finally` 清理中移除。源码与配置变更未提交或推送 Git，未混入工作区其他尚未发布的功能。

部署入口：

- `tools/author-paper-monitor/deploy/access_aws.py`：生成增量包、运行临时任务、验证后晋升后台/机构服务。

不要直接回滚到没有权限检查的旧后端或旧机构镜像。故障时优先保留拒绝访问的边界并修复新版本；旧镜像的恢复需要同步保留管理路由的访问控制。
