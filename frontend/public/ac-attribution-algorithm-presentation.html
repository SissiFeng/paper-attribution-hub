Plain-English Walkthrough

From raw research records to an AC knowledge library

The system takes a large candidate pool of research papers, normalizes it, scores every paper for AC attribution and SDL relevance, then turns the result into searchable tables, review queues, lint reports, and a multi-entity network.

11,268 papers 45,416 authors 7,486 institutions 827 graph nodes 1,512 graph edges
Speaker note: Start with the simple promise: "We are not manually reading thousands of records. We are converting raw scholarly metadata into a curated, inspectable knowledge base."

Algorithm

The five-stage pipeline

01

Normalize

Clean titles, DOI values, author names, institutions, years, venues, keywords, and provenance.

02

Attach entities

Link papers to authors and institutions, mark known AC members, and keep source provenance.

03

Score evidence

Measure AC signals, funding/acknowledgement signals, tier retrieval signal, and SDL architecture terms.

04

Classify

Assign labels: CORE, RELATED, SDL_FIELD, ADJACENT, UNCERTAIN, or EXCLUDE.

05

Publish views

Generate tables, lint reports, duplicate candidates, wiki digests, and the multi-entity network.

Labels

How the system decides what is "AC-related"

LabelPlain-English meaningUsed in AC graph?
CORE_RELEVANT Strong AC connection plus strong SDL/research relevance. Yes
RELATED_RELEVANT Meaningful AC attribution or connection, but not necessarily core flagship work. Yes
SDL_FIELD_RELEVANT Relevant to self-driving labs or automation, but no direct AC attribution. No, not in the default AC-attributed graph
ADJACENT / UNCERTAIN Related area or insufficient evidence. No by default
Speaker note: Emphasize that "field relevant" and "AC attributed" are intentionally different. The graph is not all SDL papers; it is the papers the algorithm believes should count toward AC attribution.
Where 827 comes from

The 827 nodes are the network view, not 827 papers

Papers 460

CORE + RELATED papers in the 2021-2025/2026 window.

Authors 229

Authors attached to those selected papers.

Institutions 82

Affiliations connected through those authors.

Topics 56

Topics from matched topic data or keyword fallback.

460 + 229 + 82 + 56 = 827 network nodes. The graph also contains 1,512 edges connecting papers to authors, authors to institutions, and papers to topics.

What the code supports

  • PDF/TXT/MD upload per paper.
  • PDF parsing with PyMuPDF or GROBID.
  • Section-aware chunking.
  • Hybrid BM25 + vector retrieval over chunks.
  • Full-text evidence scoring for classification.

What the current real DB shows

  • full_text_available = false for all 11,268 papers.
  • PaperChunk rows = 0.
  • PaperProposition rows = 0.
  • fulltext_evidence_score greater than 0 = 0 papers.

Translation: the algorithm currently uses Scopus/AC metadata, title, abstract, keywords, retrieval tier, funding fields, authors, and affiliations. It can use full text, but this particular imported corpus has not been full-text indexed yet.

Quality controls

The system does not just classify; it audits itself

Lint report

Finds website-blocking claims and reporting warnings before public use.

Duplicate candidates

Groups same-title/different-DOI records and recommends canonical records.

Review queue

Surfaces uncertain or risky records for human confirmation.

This matters because attribution is a claims system. The goal is not just to find papers, but to avoid publishing unsupported or duplicate claims.

One-sentence explanation

How to explain it to a non-technical audience

"We start with a large pile of research records, clean and connect the authors, institutions, topics, funding, and retrieval evidence, then the system decides which papers are truly attributable to AC and turns that into a searchable library and network map that humans can audit."

Analogy

It is like a librarian plus a fact-checker: first it shelves the papers correctly, then it marks which ones are safe to cite as AC-related.

Current limitation

It is not yet a universal AI memory box for arbitrary raw files and images. That requires running the raw-document ingestion and adding image OCR/vision.
